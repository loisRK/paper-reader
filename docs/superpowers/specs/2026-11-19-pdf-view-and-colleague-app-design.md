# PDF 보기와 동료용 앱 설계

기존 설계(`2026-11-18-paper-reader-design.md`)를 잇는다. 그 문서의 제약(127.0.0.1 전용, 개인 정보 커밋 금지, 특정 AI 도구에 묶이지 않음, 사용자 문구 한국어)은 그대로 유효하다.

## 의도와 이유

1. **원문이 PDF 모양 그대로 보여야 한다.** 지금 원문 패널은 PDF 글자를 문단으로 다시 흘려 보여 준다. 코드 목록·수식·표·2단 배치가 줄글로 풀려 읽을 수 없다(예: AIOpsLab 논문의 코드 예제). 그림·표만 잘라 붙이는 방식은 경우마다 보완이 끝없이 필요하다.
2. **개발자 동료도 같은 방식으로 쓰게 하고 싶다.** 동료는 저장소를 받아 자기 논문 폴더를 지정하고, 각자 로그인해 둔 AI 도구(Claude Code, Codex 등)로 요약을 만들고, 이 앱에서 읽고 메모한다. Zotero는 있으면 연동하는 선택 기능이다.

## 목표

- 원문 패널에서 PDF를 그대로 보고, 그 위에서 하이라이트·메모를 남긴다. Zotero에 있는 논문이면 지금처럼 Zotero에 실시간으로 반영된다.
- 요약 카드의 🔗 근거를 누르면 PDF의 해당 쪽으로 가서 그 문장을 강조한다.
- 동료가 `git clone` → `npm run setup` → `npm run reader`만으로 시작한다.
- 앱에서 논문 폴더를 지정하면 그 폴더의 PDF가 목록에 나온다. Zotero가 없어도 읽기·요약·메모가 된다.
- 앱의 "요약 만들기" 버튼이 사용자의 AI 도구를 실행해 요약을 만든다. 별도 API 키는 필요 없다.

## 만들지 않는 것

- 데스크톱 앱(.app/Electron), 코드 서명, Windows 지원
- 앱이 AI API를 직접 호출하는 기능(API 키 입력)
- 문장 중간에서 끝나는 자유 범위 하이라이트(하이라이트는 계속 문장 단위)
- PDF 편집(PDF 파일 안에 주석 쓰기)
- 여러 사람이 메모를 공유하는 기능

## 이렇게 되면 실패

- PDF 보기에서 단 하이라이트가 글로 읽기·요약 카드·Zotero에서 다른 문장에 붙는다.
- 폴더의 PDF 파일을 앱이 수정·이동·삭제한다. (앱은 PDF를 읽기만 한다.)
- AI 도구가 요약 폴더 밖의 파일을 고치거나, 논문 속 문장(프롬프트 주입)에 따라 임의 명령을 실행한다.
- Zotero가 없는 동료에게 Zotero 오류·안내가 계속 뜬다.
- 동료의 개인 경로·논문·메모가 저장소에 커밋된다.

## 접근 방식 (사용자 선택)

**앱 형태**
- **① 브라우저로 여는 로컬 앱 + `npm run setup`** ← 선택. 지금 구조를 그대로 쓰고, 대상이 개발자라 명령 한 줄이면 충분하다.
- ② Electron 데스크톱 앱: 더블클릭 실행은 되지만 Node·Python 동봉, 서명·보안 경고, 작업량이 몇 배.

**원문 보기**
- **A. PDF 보기를 기본, 글로 읽기는 탭으로 유지** ← 선택. 모양이 깨지지 않고, 휴대폰·좁은 화면에서는 글로 읽기로 바꿀 수 있다.
- B. PDF로 완전 교체: 좁은 화면에서 읽기 불편.
- C. 글 화면 유지, 코드 블록만 이미지로: 작지만 비슷한 문제가 계속 생긴다.

**요약 생성**: 사용자가 로그인해 둔 AI 도구 CLI를 앱이 실행한다(사용자 결정). API 키 방식은 제외.

**Zotero**: 선택 기능(사용자 결정).

**순서**: 0 디자인 정리 → 1 PDF 보기 → 2 논문 폴더 + Zotero 선택 연동 → 3 요약 만들기 버튼 → 4 setup·동료용 설명서. 단계마다 계획·구현·검토 후 `main`에 올린다.

## 0단계: 디자인 정리 (Apple 웹사이트 느낌)

사용자가 준 참고 문서 `docs/design/DESIGN-apple.md`(Apple 웹사이트 디자인 분석)의 **원칙과 값**을 읽기 앱에 맞게 옮긴다. 새 화면(PDF 탭 등)이 처음부터 새 디자인 위에 만들어지도록 1단계보다 먼저 한다.

- **가져오는 것**
  - 색: 글자 `#1d1d1f`, 바탕 흰색과 `#f5f5f7`, 구분선 `#e0e0e0`. 누를 수 있는 것은 파란색 하나(`#0066cc`, 키보드 포커스 `#0071e3`)만 쓴다. 지금의 청록·라임 강조색은 없앤다.
  - 글꼴: 시스템 글꼴(맥에서는 SF Pro), 본문 17px · 줄 간격 1.47, 제목 굵기 600(500은 쓰지 않음), 큰 제목은 자간을 조금 좁힌다. 한글은 Apple SD Gothic Neo로 이어진다.
  - 모양: 주요 버튼은 알약형(pill) 파란 버튼, 보조 버튼은 테두리만 있는 알약형, 작은 도구 버튼은 8px 모서리, 카드는 18px 모서리 + 얇은 선.
  - 그림자는 쓰지 않는다. 위에 고정되는 막대(상단 메뉴, 요약 카드 진행 막대)는 반투명 흰 바탕 + 흐림(backdrop blur).
  - 누를 때 살짝 작아지는 효과(`scale(0.95)`).
- **가져오지 않는 것**: 화면 전체를 채우는 제품 사진 타일, 흰색·검은색 구역을 번갈아 배치하는 방식, 56px 같은 마케팅용 큰 제목. 읽기 앱이라 글 읽기가 중심이다.
- **다크 모드**: 참고 문서에는 다크 모드 규칙이 없다. 어두운 타일 색(`#1d1d1f`, `#272729`)을 바탕으로, 글자는 흰색과 `#cccccc`, 링크와 버튼은 `#2997ff`를 쓴다. *(내 결정)*
- **바꾸지 않는 것**: 하이라이트 8색(Zotero 색과 맞춰야 함), 근거 문장 강조는 "파란색 하나" 원칙의 예외로 둔다. 근거 문장 강조는 노란 형광펜 계열의 옅은 색으로 바꿔 파란 버튼과 헷갈리지 않게 한다. *(내 결정)*
- **범위**: 대부분 `styles.css`의 색·글꼴·모양 값과 버튼·카드 스타일이다. 화면 구조와 기능은 바꾸지 않는다. 라이트·다크 모드 모두 대비를 확인한다(WCAG AA).
- 앱 이름·화면에 Apple 이름이나 로고는 쓰지 않는다. 디자인 원칙만 참고한다.

## 1단계: PDF 보기

### 화면

- 원문 패널 위에 탭 **[PDF] [글로 읽기]**. PDF 파일을 찾을 수 있으면 PDF가 기본이다. 사용자가 고른 탭은 브라우저에 기억한다. *(내 결정: 앱은 127.0.0.1 전용이라 휴대폰에서는 열리지 않는다. 좁은 창은 사용자가 탭을 바꾸면 된다.)*
- PDF는 패널 폭에 맞춰 쪽을 세로로 이어 보여 준다. 보이는 쪽 근처만 그린다(긴 논문도 가볍게). 확대/축소 버튼(맞춤 · − · +).
- PDF를 찾을 수 없으면(예제 논문, 파일 이동) PDF 탭에 이유를 보여 주고 글로 읽기로 연다.
- 다크 모드에서도 PDF 쪽은 원본 색(흰 바탕) 그대로다. *(내 결정: 색 반전은 그림 색을 망가뜨린다.)*

### 하이라이트·메모

- PDF 위 글자를 드래그하면 지금과 같은 도구 막대(🖍 하이라이트 · 📝 메모 · 색)가 뜬다.
- 선택 영역을 PDF 좌표로 바꿔, 겹치는 문장(`pdfRects`)을 찾아 **문장 단위 하이라이트**로 저장한다. 기록 형식(`notes.json`의 `highlights[].sentenceIds`)과 Zotero 연동은 바꾸지 않는다. 그래서 글로 읽기·요약 카드·Zotero에서 같은 문장에 보인다.
  - 겹침 기준은 Zotero 하이라이트를 문장에 붙일 때 쓰는 규칙(`matchSentences`)과 같다.
  - 선택이 어떤 문장에도 걸리지 않으면(그림 속 글자 등) 도구 막대를 띄우지 않는다.
- PDF 위에 하이라이트를 문장의 `pdfRects` 위치에 반투명 색 사각형으로 그린다. Zotero에서 단 하이라이트는 Zotero가 준 위치(`annotationPosition`) 그대로 그린다.
- 하이라이트를 누르면 지금과 같은 메모 창이 열린다(저장·삭제·색·충돌 안내 동일).
- 두 탭은 같은 메모 데이터를 쓴다. 한쪽에서 바꾸면 다른 쪽에도 바로 보인다.

### 요약 카드 → PDF

- 🔗 근거, "원문에서 보기" 버튼: PDF 탭이면 해당 쪽으로 스크롤해 문장 사각형을 깜빡인다. 글로 읽기 탭이면 지금과 같다.

### PDF 파일 찾기

- 추출할 때 PDF 경로와 MD5를 `source.json`에 기록한다(`pdf: { path, md5 }`, `EXTRACTOR_VERSION` +1). `digests/`는 git에서 제외되어 있어 개인 경로가 커밋되지 않는다.
- 예전 추출본(경로 기록 없음)은 아래 Zotero 재검색으로 PDF를 찾는다. 다시 추출하라는 안내는 지금처럼 `pdfRects`가 없을 때만 띄운다.
- 서버 `GET /api/papers/:id/pdf`: 기록된 경로의 파일을 `application/pdf`로 내려준다. 기록이 없거나 파일이 없으면 Zotero 항목(`source.zotero.itemKey`)에서 다시 찾는다. 그래도 없으면 404와 한국어 안내.
- 경로는 사용자 입력이 아니라 추출기가 쓴 값이다. 그래도 서버는 일반 파일이고 확장자가 `.pdf`인지 확인한다.

### PDF.js

- Mozilla PDF.js(Apache-2.0)의 배포 빌드(`pdf.mjs`, `pdf.worker.mjs`, 글자 선택 레이어 CSS)를 `src/reader/public/vendor/pdfjs/`에 **버전을 고정해 넣는다**. 라이선스 파일을 함께 둔다. npm 설치 없이 동작하는 원칙("런타임 npm 의존성 0")을 지킨다.
- 버전과 API(`getDocument`, 페이지 렌더, `TextLayer`)는 계획 단계에서 공식 문서로 확인한다.

### 1단계 범위 밖

- 그림·표 이미지 기능은 글로 읽기 탭에 그대로 둔다.
- 검색(쪽 안 글자 찾기), 목차 사이드바는 넣지 않는다.

## 2단계: 논문 폴더 + Zotero 선택 연동

- 앱 첫 화면(또는 설정 화면)에서 **논문 폴더 경로를 입력**한다. 여러 개 가능. 값은 git 제외 파일(`data/settings.json`)에 저장한다.
- 폴더 안의 PDF를 하위 폴더까지 찾아 목록에 보여 준다. 각 논문에 상태 표시: 요약 없음 / 추출됨 / 요약 완료.
- 논문 id: 파일 이름을 바탕으로 만든 안전한 이름 + 폴더 기준 경로의 짧은 해시. 파일 이름이 같아도 겹치지 않고, 다시 열어도 같은 id다. *(내 결정)*
- **목록은 하나로 합친다.** 폴더의 PDF가 이미 추출된 논문(`digests/<id>/source.json`의 `pdf.md5` 또는 `pdf.path`가 같음, 예: citekey로 추출한 것)이면 그 항목으로 보여 주고 새 id를 만들지 않는다. 폴더에 없는 기존 요약도 지금처럼 목록에 남는다. *(내 결정)*
- 앱에서 "추출" 버튼으로 바로 추출한다(지금의 `npm run extract`와 같은 추출기, 입력이 파일 경로).
- **Zotero 연결(자동)**: Zotero가 켜져 있으면 PDF가 Zotero에 있는지 확인한다. *(내 결정: ① Zotero 저장 폴더 안의 파일이면 그 첨부 항목, ② 아니면 PDF의 DOI로 Zotero 항목을 찾고, 그 PDF 첨부의 `md5`가 폴더 PDF의 MD5와 **같을 때만** 연결한다. 같은 DOI라도 다른 판본 PDF면 하이라이트 위치가 어긋나므로 연결하지 않는다.)* 찾으면 `source.zotero`를 채워 메모 연동이 켜지고, 못 찾으면 메모는 앱 안(`notes.json`)에만 저장한다. 나중에 연결되면 그때까지 쓴 메모를 Zotero로 보낸다(기존 동기화가 연결 안 된 하이라이트를 새로 만드는 것과 같은 동작).
- Zotero가 없거나 연결되지 않은 논문에는 Zotero 상태 줄 대신 "이 컴퓨터에만 저장됩니다" 한 줄만 보인다. 반복 경고 없음.
- 지금의 Zotero 기반 흐름(`/paper-search` → Zotero 등록, citekey로 추출)은 그대로 둔다.

## 3단계: 요약 만들기 버튼

**요약 내용** *(사용자 결정, 2026-11-19)*: 요약은 논문 내용만 정리한 카드다. 모델의 해석·의견(`opinion`, "💬 해석")과 "내 연구와의 연결"(`researchContextFile`)은 없앤다. 서버 검증은 opinion 항목과 분량·범위 미달(카드 수, 빠진 섹션, 결과 수치, 해설 문장 수, 긴 문장)도 문제로 보고하고 재시도한다.

> 논문의 내용을 요약하고 정리해서 이해하기 좋은 카드를 만드는거지 모델이 논문에 대한 해석을 달거나 의견을 요약에 넣으면 안됨. 이 도구의 목적은 논문을 카드뉴스처럼 핵심과 쟁점을 빠르게 파악하게 함과 동시에 논문의 내용 전체를 그걸 토대로 타고 들어가서 깊게 이해하기 위함이니까.

- 앱이 PATH에서 쓸 수 있는 AI 도구를 찾는다: `claude`(Claude Code), `codex`(Codex CLI). 설정에서 하나를 고른다. *(내 결정: 처음엔 이 둘만. 다른 도구는 같은 틀로 나중에 추가.)*
- "요약 만들기"를 누르면: 추출이 안 됐으면 먼저 추출 → 임시 작업 폴더를 만든다 → AI 도구를 그 폴더에서 비대화형으로 실행해 `digest.json`을 쓰게 한다 → **서버가** 검증(`check`와 같은 검사)을 돌린다 → 통과하면 논문 폴더의 `digest.json`을 교체한다. 실패하면 문제 목록을 주고 같은 AI 도구를 다시 실행한다(최대 3회). *(내 결정)*
- **격리**: 임시 작업 폴더에는 그 논문의 `source.json`과 `prompts/digest.md` 사본만 둔다. AI 도구는 이 폴더 안에서만 쓰기가 허용되고 명령 실행 권한은 주지 않는다(검증은 서버가 한다). 도구마다 권한 옵션의 세밀함이 달라도 저장소·논문 폴더·PDF는 건드릴 수 없다. 정확한 옵션은 계획 단계에서 공식 문서로 확인하고, 이 격리를 보장할 수 없는 도구는 지원 목록에서 뺀다. 논문 본문이 AI에게 들어가므로, 본문 속 지시를 따르지 말라는 문장을 프롬프트에 넣는다.
- 진행 상태(대기 · 추출 중 · 요약 중 · 검증 중 · 완료 · 실패)와 마지막 로그 몇 줄을 앱에 보여 준다. 취소 버튼. 한 번에 한 논문만 실행한다.
- 요청은 기존 규칙처럼 JSON 본문이 있는 POST만 받는다(다른 사이트가 몰래 실행시키지 못하게).
- 실패하면 원인(도구 없음, 로그인 안 됨, 3회 후에도 검증 실패)을 한국어로 보여 준다. 기존 `digest.json`은 새 요약이 검증을 통과했을 때만 바뀐다.

## 4단계: setup과 동료용 설명서

- `npm run setup`: Node 버전 확인 → Python 3.10+ 확인 → `.venv` 생성과 추출기 설치 → `paper-reader.config.json`이 없으면 예시에서 만들기 → AI 도구·Zotero 감지 결과 출력. 이미 된 단계는 건너뛴다. 전역 설치는 하지 않는다.
- README 맨 앞에 "동료용 빠른 시작"(clone → setup → reader → 폴더 지정 → 요약 만들기).
- 지원 OS: macOS, Linux.
