# 집중이 어려운 독자를 위한 논문 읽기 도구 (Paper Reader) 설계

## 의도와 이유

긴 줄글 논문을 처음부터 끝까지 읽기 어려운 독자(예: 주의력 문제로 긴 글에 집중하기 힘든 사람)가 많다. 기존 계획(Zotero 하이라이트 → Obsidian 양식 정리 → Cloudflare 배포)은 "읽은 뒤"의 파이프라인이라, 그 전에 **논문이 실제로 읽히게** 만드는 도구가 먼저 필요하다. 읽으면서 남긴 생각은 사용자가 이미 쓰는 Zotero·Obsidian 흐름에 그대로 이어져야 한다.

도구가 지원하는 흐름:

1. 키워드·트렌드 기반으로 **동료심사 저널 원저**만 검색·수집한다.
2. 논문마다 전체 흐름(전제 → 문제점 → 방법 → 실험 → 결과 → 한계)이 한눈에 이어지는 요약을 만든다.
3. 요약의 각 주장에서 원문의 해당 위치로 바로 이동해, 필요한 부분만 원문으로 확인한다.
4. 읽으면서 단 하이라이트·메모가 Zotero와 **실시간으로 양방향 연동**된다.
5. 다 읽으면 버튼 하나로 Obsidian 문헌 노트로 정리한다.

## 목표

- 요약만 따라가도 논문의 맥락과 흐름을 잡을 수 있다.
- 요약의 모든 원문 내용은 근거 문장에 연결되어 있고, 클릭 한 번으로 그 문장을 볼 수 있다.
- 원문은 사용자가 평소 쓰는 Zotero PDF 리더와 이어진다(페이지 단위 이동).
- 읽기 화면에서 단 하이라이트·메모가 Zotero PDF의 같은 위치에 나타나고, Zotero에서 단 것도 읽기 화면에 나타난다.
- 한 논문을 다 읽으면 요약 + 내 메모 + 서지정보가 정해진 양식의 Obsidian 노트가 된다.

## 이번에 만들지 않는 것

- Cloudflare 배포 (추후 별도 작업)
- 원문 전체 번역
- 인터넷에 공개되는 웹 서비스 (읽기 앱은 내 컴퓨터에서만 동작)
- 여러 사람이 같은 메모를 공유하는 기능 (Zotero 그룹 라이브러리 미지원)

## 이렇게 되면 실패 (프로그램이 돌아가도)

- 요약에 원문에 없는 내용이 들어간다. → 근거 문장이 없는 원문 주장은 표시하지 않는다.
- 선정 기준을 어긴 논문(preprint·학회논문 등)이 섞이거나, 확인하지 못한 지표가 추정값으로 표시된다.
- 요약이 다시 줄글 덩어리가 된다. → 섹션당 메시지 하나, 짧은 문장, 숫자·그림 우선.
- 링크가 엉뚱한 위치로 이동하거나, 하이라이트가 Zotero PDF의 다른 위치에 생긴다.
- 메모가 사라진다. Zotero 연결이 끊겨도, Obsidian 노트를 다시 만들어도 사용자가 쓴 메모는 지워지지 않아야 한다.
- 사용자의 Zotero 라이브러리에서 사용자가 만들지 않은 항목·메모를 수정·삭제한다.

## 제약

- **공개 공유 전제**: 독립 프로젝트 `Paper-Research-2026/paper-reader/`(자체 git 저장소)로 만들고, 추후 GitHub에 공개해 다른 사람도 쓸 수 있게 한다.
  - 개인 경로·계정·키를 코드에 넣지 않는다. 설정은 `paper-reader.config.json`(git 제외)에 두고, 예시 `paper-reader.config.example.json`만 커밋한다.
  - 생성 산출물(원문 추출·요약)은 저작권·개인 데이터이므로 `.gitignore`로 제외한다. 저장소에는 코드·문서·공개 라이선스(CC BY) 저널 원저 기반 예제 1개만 둔다.
  - README에 설치·설정·사용법을 둔다. 라이선스는 MIT *(제안 · 변경 가능)*.
- **Zotero**: 로컬 API(`http://localhost:23119/api/`)를 사용한다. Zotero 10 이상에서 로컬 API를 켜면 동작함을 확인했다.
  - 읽기는 인증 없이 가능하다.
  - 쓰기(Zotero 10 이상)는 처음 한 번 Zotero가 띄우는 허용 창에서 승인하면 발급되는 **로컬 키**를 쓴다. Zotero Web API 키는 필요 없다.
  - 쓰기 요청에는 `Zotero-Server-ID` 헤더가 필요하다. 다른 Zotero 인스턴스로 바뀌면 캐시를 버린다.
  - Zotero 7~9 사용자는 읽기 전용 모드로 동작한다(요약·읽기 가능, 메모 쓰기 불가 안내).
  - 식별자: Better BibTeX가 있으면 citekey, 없으면 Zotero 항목 key.
- **특정 AI 도구에 묶이지 않는다.** 요약 내용 작성만 AI가 하고, 나머지(검색·PDF 추출·검증·화면·연동)는 일반 프로그램이 한다. 파일을 읽고 쓸 수 있는 AI 코딩 도구(Claude Code, Codex, Gemini CLI, Cursor 등)라면 무엇이든 쓸 수 있다. 그 도구의 구독 외에 별도 API 키·비용은 없다.
  - 작성 규칙은 도구 중립 문서 `prompts/digest.md`, `prompts/search-summary.md`에 둔다.
  - 실행은 `npm run search`, `npm run extract`, `npm run reader` 같은 일반 명령으로 한다.
  - 도구별 단축 명령은 얇은 연결 파일로만 제공한다: Claude Code용 `.claude/skills/`, Codex 등용 `AGENTS.md`. 둘 다 같은 `prompts/`를 가리킨다.
- 상위 폴더의 스크립트·Worker는 참고만 하고, 이 프로젝트는 상위 폴더에 의존하지 않는다.
- 읽기 앱은 `localhost`에만 바인딩한다. 외부 접속을 허용하지 않는다(로컬 API는 인증 없이 라이브러리를 읽을 수 있으므로).
- 응답·요약 언어는 한국어, 전문 용어는 영문 병기.

## 접근 방식

### 전체 구조

1. **로컬 프로그램 + AI 코딩 도구 (선택)**: 검색·추출·검증·읽기 앱은 프로그램이, 요약 내용 작성은 사용 중인 AI 도구가 맡는다. 로컬 Zotero PDF를 그대로 쓰고 추가 비용이 없다.
2. Worker 웹앱 확장(OpenAI API): 클릭만으로 동작하지만 API 비용과 인증·배포 작업이 먼저 필요해 "일단 읽히게"라는 목표보다 범위가 크다.
3. Zotero 플러그인: Zotero 안에서 완결되지만 개발 난이도가 높고 Zotero 버전 변화에 취약하다.

사용자가 1을 선택했다.

### 읽기 화면 형태

처음에는 브라우저로 여는 HTML 파일 하나였지만, 파일만으로는 Zotero·Obsidian에 쓸 수 없다. 그래서 **내 컴퓨터에서만 도는 작은 읽기 앱**(`npm run reader` → `http://localhost:<port>`)으로 바꾼다. 사용자가 이 방향에 동의했다.

- Zotero 플러그인으로 만들기: 개발 난이도가 높고 버전 변화에 취약해 제외.
- Obsidian 플러그인으로 만들기: Obsidian을 안 쓰는 사람과 공유하기 어려워 제외.

## 사용자가 정한 것

- 원문은 주로 **Zotero PDF 리더**에서 읽는다.
- 링크 방식은 **B + A**: 읽기 앱 안의 원문 텍스트로 문장 단위 이동(B), 그림·표·수식 등 텍스트로 깨지는 부분은 Zotero PDF 해당 페이지로 이동(A).
- 요약의 흐름은 기존에 만든 발표용 논문 리뷰 자료와 비슷하게, 논문의 주요 내용(전제, 문제점, 실험 내용, 결과 등)이 이야기처럼 이어지고 맥락 파악이 쉬운 구조.
- 선정 기준(아래 1단계)과 세 가지 트렌드 기준.
- 메모 동작(아래 4단계)과 Obsidian 정리 버튼(아래 5단계).
- 특정 AI 도구에 묶이지 않을 것.
- GitHub에 공개해 공유할 수 있을 것.

## 구성

### 1단계: 수집 — `/paper-search <키워드·개념>`

#### 선정 기준 (사용자 지정, 필수)

- 동료심사(peer review)를 거친 **저널 원저(research article)**만 선정한다.
- arXiv 등 preprint, technical report, white paper, 블로그, 학위논문, 학회·컨퍼런스 논문, 워크숍·포스터는 선정·인용하지 않는다. *(해석: 리뷰 논문·editorial·letter·erratum도 "원저"가 아니므로 제외)*
- Scopus 또는 Web of Science 등재 저널을 우선하고, 가능하면 SCIE/SSCI 여부와 SJR 사분위(Q)를 확인해 표시한다. **검증하지 못한 지표는 추정하지 않고 "미확인"으로 표시한다.**
- 원문·서지정보는 저널 공식 landing page, DOI, 출판사 페이지에서 교차 확인한다.
- 조건을 충족하는 논문이 3편 미만이면 preprint·학회논문으로 채우지 않고, 선정 수를 줄인 뒤 사유를 명시한다.

#### 트렌드 기준 (사용자 지정)

키워드·개념에 해당하는 논문 중, 다음 세 가지 각각에 해당하는 논문을 골라 섹션별로 보여준다. 한 논문이 여러 기준에 해당하면 배지를 모두 붙인다.

| 기준 | 판정 방식 *(제안 · 변경 가능)* |
|---|---|
| 🔥 인용 급증 | 최근 12개월 인용 수와 인용 속도(인용 수 ÷ 발표 후 개월 수). 연도별 인용 추이로 증가세 확인 |
| 🌱 새 주제 | 최근 6개월(기본, 설정 가능) 발표 논문을 주제로 묶고, 직전 기간 대비 새로 나타나거나 급증한 주제의 대표 논문 |
| 🏛 저널 흐름 | 최근 기간 이 키워드 논문을 가장 많이 실은 저널 상위 N개와 각 저널의 대표 논문 |

기준별 기본 최대 5편 *(제안 · 설정에서 변경 가능)*. 각 기준에서 3편 미만이면 사유(예: "최근 6개월 저널 원저 2편뿐")를 표시한다.

#### 데이터 출처와 검증 *(제안 · 변경 가능)*

1. **후보 검색: OpenAlex** (무료·키 불필요). `type=article` + 출처 유형 `journal` 필터, 연도별 인용 추이(`counts_by_year`)·주제(`topics`)·저널 정보 사용. 연락용 이메일은 설정의 선택 항목(코드에 하드코딩 금지).
2. **유형 교차 확인: Crossref** (DOI 기준). `type = journal-article`이고 ISSN이 있는지 확인. 학회 proceedings가 저널처럼 분류된 경우(예: 시리즈 출판물)를 배제. 철회(retraction) 표시가 있으면 제외.
3. **landing page 확인**: DOI가 출판사 페이지로 정상 해석(resolve)되는지 확인하고, 카드에 공식 링크로 표시.
4. **저널 지표**
   - SJR 사분위(Q)·Scopus 등재: SCImago 공개 저널 목록(CSV)을 내려받아 ISSN으로 매칭. SJR 목록에 있으면 "Scopus 등재(SJR 기준)"로 표시. 데이터 연도를 함께 표시.
   - SCIE/SSCI·WoS 등재: 무료 공식 API가 없으므로, 사용자가 Clarivate Master Journal List에서 내려받은 파일을 설정에 지정한 경우에만 표시. 없으면 "미확인".
5. 1~3 중 하나라도 확인 실패하면 선정하지 않고, "제외된 후보"에 사유와 함께 남긴다(투명성).

#### 출력과 선택

- 출력: 검색 결과 페이지(읽기 앱의 `/search/<날짜>-<키워드>`, 동시에 `<outputDir>/_search/`에 저장). 기준별 섹션, 카드마다 번호·제목·한 줄 요약(한국어)·저널명·출판일·인용 추이·Q/SCIE/Scopus 배지(미확인 포함)·DOI 링크.
- 선택은 AI 도구와의 대화(“2, 5번 등록”) 또는 검색 결과 페이지의 [Zotero에 등록] 버튼으로 한다. *(제안 · 변경 가능)*
- 등록은 Zotero 로컬 API로 메타데이터를 저장하고, 합법적 오픈 액세스 PDF(OpenAlex `best_oa_location`)가 있으면 첨부한다. 저널 논문은 구독 PDF인 경우가 많으므로, 없으면 "기관 구독으로 PDF를 받아 Zotero에 넣어주세요"라고 안내하고 2단계는 PDF가 생긴 뒤 실행한다. *(제안 · 변경 가능)*

### 2단계: 요약 — `/paper-digest <citekey 또는 Zotero 항목>`

"요약 작성"은 AI가 **요약 내용(`digest.json`)을 쓰는 것**만 뜻한다. 화면은 읽기 앱이 `digest.json`과 원문 추출본을 합쳐 보여준다. 그래서 어떤 AI 도구를 써도 화면 모양은 같다.

1. Zotero 로컬 API에서 항목의 메타데이터, PDF 첨부 key·경로를 가져온다.
2. PDF 텍스트를 페이지·문단·문장 단위로 추출하고 각 문장에 `p{페이지}-s{번호}` ID를 부여한다. **문장별 PDF 좌표(페이지 내 사각형 목록)**도 저장한다(4단계에서 Zotero 하이라이트 위치로 사용). 섹션 제목과 그림/표 캡션 위치(페이지)도 기록한다. → `source.json`
3. AI 도구가 `prompts/digest.md` 규칙에 따라 `source.json`을 읽고 구조화된 요약 `digest.json`을 작성한다.
4. 검증 스크립트가 모든 evidence ID가 `source.json`에 있는지 확인한다. 없는 ID가 있는 원문 주장은 제거하고 보고한다.

#### 요약의 흐름 (AIOpsLab 자료 구조를 일반화)

| 순서 | 섹션 | 담는 내용 |
|---|---|---|
| 0 | Takeaway | 이 논문을 한 문장으로 + 왜 읽을 가치가 있는지 |
| 1 | 전제·배경 (Motivation) | 이 분야가 어떤 상황인지, 왜 중요한지 |
| 2 | 문제점 (The gap) | 기존 접근이 무엇을 못 하는지 |
| 3 | 핵심 아이디어 | 저자들의 해결 방향 한 줄 |
| 4 | 방법 (Method) | 구조·구성요소, 필요하면 여러 카드 |
| 5 | 실험 설정 | 무엇을, 어디서, 무엇과 비교해 시험했나 |
| 6 | 결과 | 핵심 수치(큰 숫자), 그림/표 → Zotero 페이지 링크 |
| 7 | 분석·실패 사례 | 결과가 왜 그렇게 나왔는지 |
| 8 | 한계·비판적 검토 | 저자 언급 한계 + AI의 해석(구분 표시) |
| 9 | 시사점·다음 질문 | 내 연구에 주는 의미, 원문에서 더 볼 곳 |

논문 성격에 따라 섹션을 생략·분할할 수 있다. 각 카드는 "질문형 제목 → 짧은 답 → 근거 bullet" 형태로, 이전 카드와의 연결 문장(“그래서…”, “그런데…”)으로 이어져 흐름이 끊기지 않게 한다.

**문장 유형과 근거 규칙** *(제안 · 변경 가능)*: `digest.json`의 각 항목은 `kind`를 가진다.

- `claim` (원문 내용): evidence 1개 이상 필수. 검증 실패 시 제거.
- `opinion` (AI의 해석·비판·시사점): evidence 없어도 되지만 화면에 "💬 해석" 배지로 원문 내용과 구분.
- `glossary` (용어 정의), `bridge` (카드 사이 연결 문장): 근거 불필요, 새로운 사실 주장을 담지 않음.

**"내 연구" 맥락** *(제안 · 변경 가능)*: 설정의 `researchContextFile`(선택)에 연구 주제 Markdown 경로를 지정하면 9번 섹션에 "내 연구와의 연결"을 `opinion`으로 쓴다. 없으면 9번은 "다음 질문·원문에서 더 볼 곳"만 담는다.

### 3단계: 읽기 화면 — `npm run reader`

```text
┌─ 요약 ─────────────────┐┌─ 원문 ─────────────────────┐
│ ❷ 핵심 아이디어    🔗  ││ ▶ We propose ...  ← 드래그 │
│  📝 내 메모: ...       ││   [🖍 하이라이트][📝 메모]  │
│                        ││   🟡 Zotero에서 단 메모 표시 │
├────────────────────────┴┴────────────────────────────┤
│ 진행 ███████ 9/9     [📓 Obsidian으로 정리하기]       │
└──────────────────────────────────────────────────────┘
```

- 첫 화면: 내 논문 목록(요약 있음/없음, 읽기 진행률).
- 레이아웃: 왼쪽 요약(흐름 카드), 오른쪽 원문 패널. 좁은 화면에서는 원문 패널이 아래 시트로 열린다.
- 🔗 클릭 → 원문 패널이 해당 문장으로 스크롤되고 강조된다.
- 그림·표·수식 → `zotero://open-pdf/library/items/<attachmentKey>?page=N` 링크.
- 집중을 돕는 장치 *(제안 · 변경 가능)*:
  - 상단 Takeaway 고정 + 진행 막대(읽은 카드 수)
  - 카드별 "읽음" 체크
  - 3분 모드(흐름 카드 제목·답만) / 10분 모드(근거 bullet까지) 전환
  - 집중 모드: 현재 카드와 연결된 원문 외 흐리게
  - 처음 나오는 전문 용어 hover 정의
- 디자인: 큰 숫자, 짧은 문장, 섹션당 메시지 하나. AIOpsLab 자료의 시각 언어(짙은 배경 + 포인트 색)를 참고하되 라이트/다크 모두 지원.

### 4단계: Zotero 메모 실시간 연동 (사용자 확인)

1. **원문 문장 하이라이트·메모 → Zotero PDF**: 원문 패널에서 문장(또는 여러 문장)을 골라 하이라이트하거나 메모를 달면, Zotero PDF 첨부 아래에 같은 위치의 **highlight annotation**(메모는 annotation comment)이 생긴다. 위치는 2단계에서 저장한 문장 좌표를 쓴다. 색은 Zotero 기본 하이라이트 색 중 선택.
2. **Zotero → 읽기 화면**: Zotero PDF 리더에서 사용자가 직접 단 하이라이트·메모도 원문 패널의 해당 문장에 표시된다. 읽기 앱이 몇 초 간격으로 변경분(`since=<version>`)을 가져온다. 좌표로 문장에 매칭하고, 매칭이 안 되면 해당 페이지 끝에 표시한다.
3. **요약 카드 메모 → Zotero 노트**: 요약 카드("❷ 핵심 아이디어" 등)에 단 메모는 Zotero 논문 항목의 child note 하나("Paper Reader 메모")에 카드별 제목 아래로 모아 저장한다.
4. **안전 규칙**
   - 읽기 앱은 자신이 만든 annotation·note만 수정·삭제한다. 사용자가 Zotero에서 만든 것은 읽기만 한다. 자신이 만든 항목은 태그(`paper-reader`)로 구분한다.
   - Zotero가 꺼져 있거나 쓰기가 실패하면 메모를 로컬 대기열(`<outputDir>/<citekey>/pending.json`)에 보관하고, 화면에 "Zotero 연결 대기 중"을 표시한 뒤 연결되면 다시 보낸다. 메모는 절대 버리지 않는다.
   - 같은 대상을 양쪽에서 동시에 고친 경우 Zotero 쪽 버전을 기준으로 하고, 읽기 앱 쪽 내용은 덮어쓰기 전에 사용자에게 보여준다 *(제안 · 변경 가능)*.

### 5단계: Obsidian으로 정리하기 버튼 (사용자 확인)

- 버튼을 누르면 설정의 Obsidian Vault 경로에 문헌 노트를 쓰고, `obsidian://open` 링크로 바로 연다.
- 노트 양식: 설정의 템플릿 파일. 기본 템플릿은 Obsidian Zotero Integration 플러그인용 문헌 노트 템플릿 구조를 따른다(속성, 논문 정보 callout, 참고문헌, Zotero 노트, `## 내 메모` 보존 영역, PDF·첨부). 여기에 다음을 추가한다.
  - AI 요약 흐름(카드 순서대로, `claim`/`opinion` 구분 유지)
  - 내 하이라이트·메모(원문 인용 + `zotero://open-pdf/...?page=N&annotation=<key>` 링크)
  - 요약 카드 메모
- 저장 위치: 기본 `Zotero/@<citekey>.md` *(제안 · 변경 가능, 기존 Zotero Integration 플러그인 설정과 동일)*.
- 같은 노트가 이미 있으면 `{% persist %}`로 표시된 `## 내 메모` 보존 영역은 그대로 두고 나머지만 갱신한다. 덮어쓰기 전 기존 파일을 `<outputDir>/<citekey>/backup/`에 백업한다.
- Obsidian을 쓰지 않는 사용자는 이 버튼을 숨기거나 Markdown 파일 내보내기로 쓴다.

### 산출물 위치

설정의 `outputDir`(기본 `./digests`, git 제외). Obsidian Vault 안의 폴더로 지정할 수도 있다.

```text
<outputDir>/
├── _search/<YYYY-MM-DD>-<keyword>.json   # 검색 결과
└── <citekey>/
    ├── source.json    # 추출 원문 + 문장 ID + 문장 좌표
    ├── digest.json    # 구조화 요약
    ├── progress.json  # 읽음 체크·모드
    ├── pending.json   # Zotero 전송 대기 메모
    └── backup/        # Obsidian 노트 덮어쓰기 전 백업
```

## 만드는 순서 (단계별로 바로 쓸 수 있게)

1. 검색 + 요약 + 읽기 화면 (읽기 전용)
2. Zotero 메모 실시간 연동
3. Obsidian 정리 버튼

## 빌더에게 맡기는 것

- PDF 텍스트·좌표 추출 라이브러리 선택(예: PyMuPDF; 프로젝트 로컬 가상환경에 설치, 전역 설치 금지)과 문장 분리 규칙.
- Zotero annotation 위치 형식(`annotationPosition`의 `pageIndex`·`rects`)으로의 좌표 변환.
- 2단 레이아웃·각주·참고문헌 처리 방식(참고문헌은 원문 패널에서 접어둠).
- 읽기 앱의 프레임워크와 구현 언어(Node 권장), 포트.
- 도구별 연결 파일의 세부 형태와 `prompts/` 문구 세부.
- Obsidian 템플릿 렌더링 방식.
- 테스트: 추출(ID·좌표 안정성), evidence 검증, Zotero 연동(로컬 API 모의 서버), 메모 대기열, Obsidian 보존 영역 유지에 대한 단위 테스트를 `tests/`에 둔다.
